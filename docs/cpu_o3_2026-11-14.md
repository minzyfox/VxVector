# The CPU kernel at -O3 (November 14, 2026)

`scripts/build.sh` and `scripts/build_linux_worker.sh` now compile `src/kmeans.vx` with `vxc -O3`. Before, they used Vx's default, `-O0`.
The results are the same bits, and CPU training is about 6 times faster. Every CPU user gets this, including the Linux PostgreSQL image.
This is the first part of Step 7's optimized CPU baseline. The kernel still uses one thread and no explicit SIMD.

Vx is `423a10db`, the current pin. The device is an Apple M2 Pro running macOS 27.2.1. The build manifest (`build/vx-build-info.json` and `build/linux/vx-build-info.json`) now records `opt_level`.

## Why the bits do not change

`-O3` may reorder or fuse float arithmetic only where an operation allows it. Vx writes that permission as a `fastmath` attribute, or as a fused multiply-add intrinsic, in the LLVM dialect it emits.
Neither appears at `-O0` or at `-O3`. All 78 float operations of the `-O3` kernel are plain, such as `llvm.fadd %a, %b : f64`.
[scripts/check_kernel_codegen.py](../scripts/check_kernel_codegen.py) now checks this on every run, in the new case `exact_math_o3` ([log](evidence/cpu_o3_codegen_2026-11-14.jsonl)).

## A finer clock on macOS

One test failed at first under `-O3`: a small training phase took 0.0 seconds. macOS's `CLOCK_MONOTONIC` counts in microseconds, and the phase took less than one.
[src/data_path.c](../src/data_path.c) now uses `CLOCK_MONOTONIC_RAW` on macOS, which counts in about 42 ns. Linux keeps `CLOCK_MONOTONIC`, which counts in nanoseconds there. The test passed in 5 of 5 repeated runs.

## Linux and PostgreSQL

The Linux worker, extension, and image were rebuilt at `-O3` (Linux `kmeans.o` SHA-256 `607c69d1…`) ([log](evidence/cpu_o3_linux_2026-11-14.txt)).
The image, extension, snapshot, and synthetic recall checks passed. Real-data recall passed its gates on 3,072 queries ([log](evidence/cpu_o3_linux_real_recall_2026-11-14.jsonl)).

Compared with the [`-O0` run](evidence/linux_real_recall_2026-11-14.jsonl) earlier that day, every field from Vx training is the same: each query's recall, each node count, and each Vx mean.
Only `internal_mean`, and the `difference` that uses it, changed. It is the recall of VectorChord's own internal k-means, which varies from run to run.
